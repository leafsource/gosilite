# 登录失败限制与账号锁定

## Report

## [S1] Problem

当前登录仅验证账号密码，攻击者可以在多实例环境中持续猜测密码。系统参数管理虽可维护键值配置，但没有与登录安全联动的失败次数、统计窗口和账号锁定规则。

## [S2] Design

### S2.1 可配置规则

在 `conf/conf.yaml` 中提供以下部署级默认值；同名 `system` 类型参数启用且合法时覆盖 YAML，管理员可通过现有参数管理页面即时调整：

| 参数键 | 默认值 | 含义 |
|---|---:|---|
| `sys.login.max_failures` | `5` | 统计窗口内触发临时锁定的失败次数 |
| `sys.login.failure_window_minutes` | `15` | Redis 临时失败计数的窗口分钟数 |
| `sys.login.lock_minutes` | `30` | 达到临时阈值后的临时锁定分钟数 |

失败阈值必须在 1–9 之间，分钟参数必须是正整数。参数不存在、禁用、为空或非法时安全回退至 YAML 默认值，且写 Hertz 日志。运行时每次登录从参数服务读取当前值，因此管理端保存后无需重启即可生效；YAML 默认值则需要重启才生效。

### S2.2 失败计数与锁定

限制按登录账号（标准化为 trim 后的小写）聚合，不按 IP 聚合；Redis key 使用项目专属前缀，以保证多副本共享状态。

1. 每次登录先检查该账号是否临时锁定或永久锁定；任一锁定时直接拒绝。
2. 账号不存在、密码错误、账号停用和已锁定都对客户端返回相同凭据错误，不暴露账号存在或锁定状态。
3. 密码错误时增加 Redis 窗口计数。首次失败设置 `failure_window_minutes` TTL；达到 `max_failures` 时写入临时锁定 key，TTL 为 `lock_minutes`。
4. 每次密码错误同时对真实用户原子增加持久化累计失败数。临时锁定期内仅错误密码继续累计，正确密码只被拒绝。达到 10 次时设置永久锁定；永久锁定优先于临时锁定。
5. 成功登录清除 Redis 的临时失败/锁定 key，并将用户持久化累计失败数清零。
6. 管理员在用户管理中提交非空重置密码时，清除该用户的永久锁定及累计失败数，也清除 Redis 临时失败/锁定 key。仅编辑资料、状态、角色或岗位不得解锁。

Redis 不可用时登录失败采用 fail-closed：拒绝登录并记录内部错误；这样不会在缓存故障时取消暴力破解防护。

### S2.3 持久化与管理端

`system_user` 增加 `login_failure_count`（默认 0）和 `login_permanently_locked`（默认 false）。管理员用户列表增加“登录安全”信息，永久锁定用户显示“永久锁定”；用户编辑表单的重置密码提示明确说明“重置密码将解除永久锁定”。不新增独立解锁按钮。

先修改 IDL 与最终发布 schema/当前开发迁移源，再重新生成 gorm 模型与 HTTP DTO；禁止手改生成物。用户管理员 DTO 只返回永久锁定布尔值和累计失败次数，不返回临时 Redis 状态。

### S2.4 测试边界

测试覆盖：默认与非法参数回退、窗口内计数、临时锁定、永久锁定、统一外部错误、成功清零、管理员重置密码解锁、Redis 异常 fail-closed，以及跨 Service 实例共享状态。前端验证参数表单可编辑预置参数，并在用户列表显示永久锁定。

## [S3] Out of Scope

- 不按 IP、设备指纹或验证码实施限流。
- 不提供用户自助找回密码、短信/邮件验证或管理员手动解锁按钮。
- 不记录或展示密码原文、错误密码或 Redis 临时计数。
- 不改变现有 JWT、refresh token 或权限契约。
